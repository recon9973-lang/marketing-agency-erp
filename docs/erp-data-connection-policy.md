# ERP 데이터 연결 상태 정책 (전역)

> 목표: 모든 외부 데이터가 필요한 모듈을 전수 파악하고, **실측 미연결인 곳은 목업을 실측인 척
> 보여주지 않는다**. "미연결"을 명시하고 연결 방법을 안내한다. 미구현 모듈은 레지스트리에
> 등록만 하면 연결 상태 UI를 자동으로 얻는다(확장 가능).

## 1. 단일 진실: 연동 레지스트리

`src/server/integrations/status.ts`의 `getIntegrationStatuses()`가 **모든 외부 연동의 단일
진실**이다. 각 항목: `key·label·category·configured(env 실측)·envVars·usedIn·fallback`.
→ 새 데이터 소스는 **여기에 항목 하나 추가**하면 연결 상태를 얻는다. 소비자는 항상 이 레지스트리를 조회한다.

## 2. 3가지 연결 상태 (표시 규칙)

| 상태 | 조건 | 화면 표시 |
|---|---|---|
| 🟢 **연결됨(실측)** | `configured=true` + 호출 성공 | 실제 데이터 + `실측` 배지 |
| 🟡 **데모** | `configured=false`, 단 데모 표시가 유의미(세일즈/미리보기) | 데모 데이터 + **`데모(미연결)` 배지** (실측 아님 명시) |
| ⚪ **미연결** | `configured=false`, 가짜 수치가 오해를 부르는 곳 | 데이터 숨김 + **`미연결` 배지 + 연결 안내(envVars)** |

**원칙**: 절대 가짜 데이터를 배지 없이 실측처럼 보여주지 않는다. 숫자가 의사결정·고객문서에
쓰이는 곳(검색량·지표·매출)은 🟡가 아니라 ⚪(미연결)로 — 오해 차단 우선.

## 3. 소비자 계약 (모든 데이터 소비 UI)

1. 레지스트리에서 자신의 연동 상태를 조회한다(`isIntegrationConfigured(key)` 또는 서버에서 상태 주입).
2. 연결됨 → 실측 데이터 + 티어 배지.
3. 미연결 → `<ConnectionBadge integrationKey=... />` + 연결 안내(무슨 env를 넣으면 켜지는지).
4. 데이터 접근은 가능하면 **단일 창구**(예: 검색 데이터 = `SearchDataPort`)를 통한다.

## 4. 공용 컴포넌트 (신규·additive)

- `ConnectionBadge` — 레지스트리 key로 연결/미연결·연결안내를 일관 표시(ERP 전역).
- `TierBadge`(기존) — 연결된 데이터의 출처(실측/AI) 구분.
- 중앙 대시보드 = `/integrations`(이미 존재) — 전 연동 상태 한눈에.

## 5. 확장 설계 (미구현 → 구현 시 자동 연결)

- 새 모듈이 외부 데이터를 쓰게 되면: ① `status.ts`에 항목 추가 → ② 소비 UI에 `ConnectionBadge`
  삽입 → ③ env 채우면 자동 실측. **코드 흐름 변경 없이 켜짐.**
- 데이터 소스가 여럿인 도메인은 포트 추상화(SearchDataPort 방식)로 묶어 목↔실측 무중단 스왑.

## 6. 실행 (감사 결과 기반)

1. 전수조사(에이전트) → 미연결인데 데모를 실측처럼 보이는 지점 목록화.
2. `ConnectionBadge` 신설(공용, additive).
3. 우선순위(의사결정·고객문서에 숫자 노출되는 곳)부터 데모→미연결 전환.
4. 레지스트리 누락 항목 보강(GEO 4-AI·검색 데이터 등).
5. 각 단계: 기존 화면은 additive·소규모, `schema.prisma` 무변경, 테스트·스크린샷 검증.

## 7. 정직화 2차 (실행 로그)

정적 배지·조용한 폴백·미배선 스캐폴드까지 "실측처럼 보이는" 잔여 지점 정리.

| 항목 | 문제 | 조치 | 상태 |

| keyword-rank.ts | 미배선 스캐폴드가 라이브처럼 보임 | 헤더에 dead-scaffold 명시 + 라이브 대체(marketing/) 지시 | ✅ |
