# 컨설팅 제안 덱 업그레이드 기획 — 16슬라이드 표준 × ERP 실측 연결

> 목적: 수작업 제안 덱("VENOM&MARKEPICK 마케팅 제안", 16슬라이드)을 ERP가 **지역+진료과(+병원명) 입력만으로 실측 근거와 함께 자동 초안 생성**하도록 업그레이드한다.
> 원칙: 덱의 모든 수치는 **실측 소스에 근거**한다(샘플·라운드 예시 금지). 신호 없는 항목은 정직하게 미연동 표기.
> 범위: 본 문서는 **데이터 연결 계획**이다. PPT 렌더링(pptxgenjs 매핑)은 후속.

---

## 1. 덱 방법론과 ERP 흐름 정합

덱 p13 방법론 = **분석 → 제안 → 진행 → 보고**. ERP 대응:

| 덱 단계 | 내용 | ERP |
|---|---|---|
| 분석 | 현황·경쟁병원·키워드 | `/market` 상권분석 + 키워드 실측 + 경쟁사 |
| 제안 | 예산·필요 채널 제안 | 수주 진단(대응 방향) + 리포트/제안서 |
| 진행 | 월간 계획·노출·브랜딩 | WorkItem(실행보드) + 채널 연동 |
| 보고 | 월 결과·재분석 | `/insights` 상담 진단(진행 거래처) |

수주(90%)는 `/market`, 진행 거래처(10%)는 `/insights` — 두 진입점 모두 공용 합성 엔진(`consulting-review.ts`) 사용.

## 3. 데이터 연결 상태

### ✅ 이번 커밋에서 연결 (덱 p9 키워드 분석표)
- `src/server/market/keyword-scan.ts` — 지역+진료과 시드 키워드 생성 → 실측:
  - **월간 검색수 PC/Mobile/합계 · 경쟁도**: 네이버 검색광고 키워드도구(`fetchKeywordExpansion`, `NAVER_AD_*`)
  - **블로그 발행 문서수 → 포화도**: 네이버 블로그 검색(`fetchBlogDocCount`, `NAVER_CLIENT_*`)
- `scanMarketKeywords` 액션 + `/market` "🔎 키워드 실측" 표(검색량·경쟁도·블로그·포화도). 미연결 시 정직 강등.

### ✅ 이미 연결돼 있던 실측(재사용)
- 상권: 인구·병원밀집·수요·소득·접근·개원추세·스코어카드·**수주 진단**(덱 p8·p12)
- 경쟁사 상위 표본: `naver-local`(덱 p3·p5·p8)
- 진행 거래처 채널·순위·키워드: `insights` 리포지토리·`exposure`·`PlaceRankRecord`(덱 p7 순위/보고)

### 🔴 신규 데이터(후속, 대부분 prod 전용·검증 필요)
1. **CPC 입찰가**(p4) — 네이버 검색광고 **입찰가 추정 API**(ManagePage bid) 신규. 현재 `adDepth`(파워링크 평균 노출수)로 경쟁 근사만 가능. 정식 입찰가는 별도 서명 요청 구현 필요.
2. **채널별 점유율 bar**(p6) — 키워드별 각 채널(파워링크·플레이스·블로그·카페) 상위 노출에서 본원 vs 경쟁 슬롯 점유 계산. `exposure`/rank 데이터 위에 집계 로직 신규.
3. **플레이스 N1/N2 점수**(p7) — 네이버 플레이스 랭킹 점수는 공식 API 없음 → 스크래핑(무겁고 정책 주의). 순위·방문·블로그·저장수는 `exposure` 확장으로 근사.

## 4. 업그레이드 산출물 목표

`analyzeRegion` + `scanMarketKeywords` + 수주 진단이 모이면, 덱의 **분석·제안 파트(p1·p6~9·p12)**가 실측으로 자동 채워진다. 남은 개념 슬라이드(p2·p10·p11·p13)는 정적 템플릿, 포트폴리오(p14·p16)는 DB 생성.

### 다음 단계(우선순위)
1. **채널 SOV 집계**(p6) — 가장 임팩트 큰 신규. 키워드×채널 노출에서 본원/경쟁 점유율.
2. **플레이스 순위 표 확장**(p7) — 경쟁 플레이스 방문·블로그·저장수 근사.
3. **CPC 입찰가 API**(p4) — 검색광고 bid API 연동(예산 제안 근거).
4. **PPT 매핑** — 위 실측 블록을 16슬라이드 pptxgenjs 템플릿에 배치(별도 작업).
