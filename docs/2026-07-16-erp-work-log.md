## 1. 계약서 · 서명/도장

**목표**: 계약서 서식의 도장/서명이 너무 크거나 위치가 어색하고, 서명 가독성이 낮은 문제 개선.

- **도장 크기 축소**: 96px → **60px** (`ContractDocument.tsx`의 `SignBlock`)
- **서명 위치 통일**: 갑(고객) 서명을 을 도장처럼 **대표 이름 옆 "(서명 또는 인)" 자리에 겹쳐** 표시
- **"(서명 또는 인)" 양쪽 표시**: 갑·을 모두 이름 옆에 노출
- **서명 크기·가독성**: 높이 52 → 57 → **72px**, 최대너비 150 → 210px, `filter: contrast(1.8) brightness(0.65)` 로 획을 진하게
- **겹침 비침 제거**: 서명/도장이 있으면 뒤 안내문구를 `text-black/15` 로 낮춰 획과 겹쳐 비치는 문제 해결

관련 커밋: `2242631`, `3d8876f`, `8018148`

## 2. 설문 시스템

**목표**: 설문을 계약서와 동기화하고, 실제 운영 서식(시작/중간 점검)에 맞춰 재설계.

### 2-1. 계약서 → 설문 동기화 (`72063ae`)
- 계약서 **대행범위(scopeItems)** → 설문 카테고리 매핑(블로그/플레이스/SNS/검색광고)
- 계약서 **거래처명** → 설문 "병원명" 기본값 prefill
- 공개 설문 폼에 **"계약서 자동입력" 배지** 표시(수정 가능)

### 2-2. 시작/마감 점검 2종 설문 + 기타 직접입력 (`0b88424`)
업로드된 실제 서식 2종을 코드로 반영:
- **STEP 1 「마케팅 시작 설문」** (진행 전 1회) — 진료과목·환자현황·경쟁사·광고방향·강점·치료철학·채널 계정 등. 대행범위에 맞춰 채널 계정 문항 조건부 노출.
- **STEP 2 「중간 점검 설문」** (매달 마감 후, 회차 누적) — 만족도(1~10)·채널별 효과·신환 변화·콘텐츠 피드백·경쟁사 동향·매니저 소통 등.
- 계약 상세에 **「시작 설문 생성」 / 「마감 점검 설문 생성」** 두 버튼.
- **choice 문항마다 "기타(직접 입력)"** 옵션 → 선택 시 직접 타이핑 입력창 노출(`PublicSurveyForm.tsx`).
- 콘텐츠 기획 자동생성은 응답에 `keywords` 있을 때만(불필요한 빈 초안 방지).

관련 파일: `src/server/actions/surveys.ts`, `src/components/survey/PublicSurveyForm.tsx`, `src/components/contracts/ContractSurveys.tsx`

## 3. 성능 개선

**증상**: "탭 클릭 시 항상 로딩이 길다"(베놈 관리자 대비 느림).

### 3-1. 진단 과정
- 대시보드는 이미 병렬 조회(`Promise.all`)+Suspense로 최적화돼 있었음.
- 라우터 캐시(`staleTimes.dynamic`)가 30초로 짧아 재방문마다 재조회.
- `(erp)/loading.tsx` 가 전체화면 로더(FunLoader)라 왕복 대기 구간을 통째로 덮음.

### 3-2. 조치
- **라우터 캐시 연장** 30 → **120초** (`next.config.ts`, `5c313b6`) — 한 번 연 탭 재방문 즉시 전환.
- **대시보드 스트리밍**(`4dee135`) — 인증만 대기하고 무거운 조회를 `<Suspense>` 안으로 → 골격 먼저.
- 전환 로딩 스켈레톤 실험 후 텍스트 있는 FunLoader로 원복(`37aaaea` → `1d6c129`).

### 3-3. ★ 핵심 원인·해결 — 리전 정렬 (`814b2b0`)
- **발견**: DB(Neon)는 **싱가포르**인데 Vercel 함수는 **미국 기본 리전** → 페이지마다 **미국↔싱가포르 왕복**이 반복.
- **해결**: `vercel.json` 에 `"regions": ["sin1"]` → 함수를 **DB와 같은 싱가포르로 이동**.
- 결과: 함수↔DB 같은 리전(초고속) + 한국과 거리 단축 → **체감 속도 확연히 개선**(사용자 확인).
- 데이터 이전 없이 코드 한 줄로 해결.

> 교훈: DB가 어디에 있는지부터 확인. "서버만 아시아로" 옮기면 오히려 악화 — 함수와 DB를 **같은 리전**에 두는 것이 핵심.

## 4. 배포 안정화

**증상**: "코드를 바꿔도 화면이 안 변한다 / Building에서 안 넘어간다."

- **원인 1 — `[skip ci]` 자동봇**: `.github/workflows/project-state.yml` 이 매 push마다 `PROJECT_STATE.md` 를 자동 커밋(`[skip ci]`)해 **HEAD가 skip-ci 커밋이 되어 Vercel이 배포를 건너뜀**.
  - **조치**: 워크플로를 **수동 실행(workflow_dispatch) 전용**으로 변경 → 자동 push 중단 (`7207d90`).
- **원인 2 — 빌드 무한대기**: 빌드 스크립트의 DB 단계(마이그레이션/백필)가 락/연결 대기로 멈추면 `next build` 까지 못 감.
  - **조치**: 각 DB 단계에 **`timeout` + `|| echo`** 방어 → 멈춰도 건너뛰고 빌드 완료 (`3a2f6fc`, `package.json`).

## 5. 인증 / 로그인 (집중 트러블슈팅)

**목표**: 로그인 비밀번호를 앱에서 관리하고, 잠금 시 복구 가능하게.

- **로그인 비밀번호 관리 화면**(`f08cce1`): `User.passwordHash`(scrypt) 추가 → 설정 → "로그인 비밀번호"에서 변경. 로그인은 **DB 해시 우선, env `ADMIN_PASSWORD` 는 복구용** 병행 검증. (`src/server/security/password.ts`, `src/server/auth.ts`)
- **세션 방어**(`94f7783`): 새 컬럼(`deniedFeatures`) 미반영 시에도 `getCurrentUser` 가 던지지 않도록 폴백 → 로그인 직후 되튕김 방지.
- **부트스트랩 관리자**(`43665dd`): Vercel env와 무관하게 **항상 로그인 가능한 고정 계정**(scrypt 해시만 코드 보관, 원문은 코드에 없음). 잠금 방지용.
- **원인 규명**: 로그인 실패의 실체는 대부분 **옛 배포가 서빙되던 것**(위 4번 배포 문제). 라이브 코드 버전 확인용 임시 진단(`/api/version`)으로 특정 후, **정상화 확인되어 진단 코드 전부 제거**(`e7dc300`).

> 운영 전환 시 부트스트랩 계정은 제거/비번 교체 권장.

## 7. 이메일 · 도메인 인프라

**목표**: Vercel을 매번 만지지 않고 **이메일로 로그인·초대·비번 복구**.

- **Resend 발송 연동**: 코드 수정 없이 기존 next-auth Email(nodemailer) 에 물림 — `EMAIL_SERVER=smtps://resend:<API_KEY>@smtp.resend.com:465`. 매직링크 로그인 메일 **정상 발송·클릭 확인**.
- **커스텀 도메인 `erp.seokorea.org`**: Vercel `marketing-agency-erp` 프로젝트에 추가 → DNS CNAME → SSL 발급 → 접속됨.
- **Resend 도메인 인증 `seokorea.org`**: DKIM(TXT)·SPF(MX/TXT) 레코드 추가 → **전부 Verified** → 아무 수신자에게나 발송 가능(스팸함 회피).
- **마무리 env**(사용자 설정): `EMAIL_FROM=noreply@seokorea.org`, `AUTH_URL=https://erp.seokorea.org`, (선택) `CANONICAL_HOST=erp.seokorea.org`.
- **URL 통합 대비**: `middleware.ts` 에 `CANONICAL_HOST` 리다이렉트 추가(설정 시 모든 접속을 한 주소로 통일; 미설정 시 무동작) (`84446f9`).
