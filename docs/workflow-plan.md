# 업무 워크플로우 확장 기획 (backlog.md 검토 회의 결과)

2026-07-03 검토. 원칙: **외부 API/계약이 필요한 항목은 기존 연결된 자원(Neon Postgres)으로
임시 구현하거나 뒤로 미룬다.** 대표가 선택을 사전 승인하여 아래 결정대로 순차 구현한다.

## 구현 순서와 결정

### 1차 — 즐겨찾기 ✅ (착수)

- **검토한 옵션**: (a) 메뉴/화면 즐겨찾기, (b) 거래처 즐겨찾기, (c) 둘 다.
- **결정**: (b) 거래처 즐겨찾기부터. 화면 수가 8개뿐이라 메뉴 즐겨찾기는 효용이 낮고,
  거래처는 수십~수백 개로 늘어나 상단 고정의 효용이 크다. 목록에서 별(★) 토글,
  즐겨찾기가 목록 상단에 고정. 사용자별 저장(직원마다 다름).
- **모델**: `ClientFavorite(userId, clientId, unique)`.

### 2차 — 내부 채팅

- **검토한 옵션**: (a) WebSocket 실시간(Pusher/Ably 등 외부 서비스 필요),
  (b) 폴링 기반(주기적 새 메시지 확인), (c) 이메일형 쪽지.
- **결정**: (b) 폴링 기반. Vercel 서버리스는 WebSocket 상시 연결이 불가하고
  외부 실시간 서비스는 API 계약이 필요하므로 원칙에 따라 폴링(5~10초)으로 시작.
  UI는 채팅형으로 만들어두고, 추후 실시간 서비스 연결 시 전송 계층만 교체.
- **모델**: `ChatRoom(1:1/그룹)`, `ChatMember`, `ChatMessage`. 협업방(4차)과 같은 모델 공유.

### 3차 — 파일 전달

- **검토한 옵션**: (a) Vercel Blob(토큰 활성화 필요), (b) NAS(장비 정보 필요),
  (c) DB(Postgres bytea) 저장.
- **결정**: (c) 임시로 DB 저장, 파일당 4MB 제한(무료 DB 용량 0.5GB 고려).
  채팅/협업방에 첨부 형태로 제공. 용량이 커지면 Vercel Blob 또는 NAS로 이전
  (저장 인터페이스를 분리해 교체 가능하게 설계).

### 4차 — 업무 협업방

- **결정**: 거래처(또는 주제) 단위 방 = 2차 채팅방의 그룹형 + 파일(3차) +
  관련 업무 링크를 한 화면에. 멤버 초대는 직원 목록에서 선택.

### 5차 — 카드뉴스 제작

- **검토한 옵션**: (a) AI 이미지 생성 API(계약 필요), (b) 템플릿+텍스트 편집기(브라우저 캔버스).
- **결정**: (b) 템플릿 기반 편집기. 브랜드 컬러 템플릿 몇 종 + 문구 입력 → PNG 다운로드.
  외부 API 불필요. AI 생성은 추후 계약 시 추가.

## 보류 (외부 계약/자격 증명 필요 — 준비되면 착수)

| 항목 | 필요한 것 |
|---|---|
| 카카오톡 전송 | 카카오 비즈메시지/알림톡 발신프로필 계약 |
| 이메일 발송 | 발송 서비스(Resend/SES 등) 또는 SMTP 계정 |
| NAS 연동 | NAS 종류·주소·계정, 외부 접근(포트/VPN) 방식 |
| 검색량 조회 | 네이버 검색광고 API 키 (무료 발급 가능 — 대표 계정으로 발급 필요) |

## 공통 설계 메모

- 모든 신규 테이블은 additive라 배포 시 `prisma db push`로 자동 반영된다.
- 권한은 기존 §1 인프라(requireCurrentUser/requireClientAccess/scope) 재사용.
- 민감 동작은 기존 audit 로그 규약을 따른다.
